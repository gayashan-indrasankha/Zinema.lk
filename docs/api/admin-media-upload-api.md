# Admin Media Upload API

## Overview

The Admin Media Upload API lets admin users upload media files to S3-compatible object storage and create the related `MediaAsset` metadata record after the upload succeeds.

All endpoints require:

```http
Authorization: Bearer <admin-jwt-access-token>
```

Required role:

```text
Admin
```

This API supports image uploads and source video uploads. Source video uploads can create and enqueue a video processing job, but this endpoint does not run FFmpeg inline, transcode media during the request, or generate HLS output by itself.

## Endpoint

```text
POST /api/admin/media-assets/upload
```

Content type:

```http
multipart/form-data
```

## Form Fields

```text
file
title
assetType
movieId
seriesId
episodeId
collectionId
```

Required:

- `file`
- `title`
- `assetType`
- At least one catalog relation: `movieId`, `seriesId`, `episodeId`, or `collectionId`

Optional:

- Other catalog relation IDs when the asset needs to be linked to more than one catalog item.

Derived by the API:

- `contentType`
- `fileName`
- `fileSizeBytes`
- `storageKey`
- `publicUrl`
- `status`

Uploaded assets are saved with status:

```text
Uploaded
```

## Automatic Processing Queue

When a completed upload has:

```text
assetType=video-source
contentType=video/mp4
```

the API creates a video processing job for the new media asset and moves it into the existing `Queued` state.

The upload response still returns the `MediaAsset` DTO. Admin clients can inspect the queued job through:

```text
GET /api/admin/processing-jobs?mediaAssetId={mediaAssetId}
```

Image uploads such as posters and backdrops are not queued for processing.

## Validation

Allowed content types:

- `image/jpeg`
- `image/png`
- `image/webp`
- `video/mp4`

Default max file size:

```text
524288000 bytes
```

The API rejects:

- Empty files.
- Files larger than the configured max size.
- Unsupported content types.
- File names containing path separators, invalid file-name characters, or `..`.
- Requests without a related catalog item.
- Requests with catalog IDs that do not exist.

## Storage Key Format

Storage keys are generated by the backend:

```text
media-assets/{yyyy}/{MM}/{guid}-{safe-file-name}
```

Example:

```text
media-assets/2026/06/11111111222233334444555555555555-demo-poster.jpg
```

## cURL Example

```bash
curl -X POST "http://localhost:5145/api/admin/media-assets/upload" \
  -H "Authorization: Bearer <admin-jwt-access-token>" \
  -F "title=Demo Poster" \
  -F "assetType=poster" \
  -F "movieId=00000000-0000-0000-0000-000000000001" \
  -F "file=@poster.jpg;type=image/jpeg"
```

Source video upload example:

```bash
curl -X POST "http://localhost:5145/api/admin/media-assets/upload" \
  -H "Authorization: Bearer <admin-jwt-access-token>" \
  -F "title=Demo Movie Source" \
  -F "assetType=video-source" \
  -F "movieId=00000000-0000-0000-0000-000000000001" \
  -F "file=@source.mp4;type=video/mp4"
```

## PowerShell Example

```powershell
$headers = @{
    Authorization = "Bearer <admin-jwt-access-token>"
}

$form = @{
    title = "Demo Poster"
    assetType = "poster"
    movieId = "00000000-0000-0000-0000-000000000001"
    file = Get-Item ".\poster.jpg"
}

Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:5145/api/admin/media-assets/upload" `
    -Headers $headers `
    -Form $form
```

PowerShell source video upload:

```powershell
$headers = @{
    Authorization = "Bearer <admin-jwt-access-token>"
}

$form = @{
    title = "Demo Movie Source"
    assetType = "video-source"
    movieId = "00000000-0000-0000-0000-000000000001"
    file = Get-Item ".\source.mp4"
}

Invoke-RestMethod `
    -Method Post `
    -Uri "http://localhost:5145/api/admin/media-assets/upload" `
    -Headers $headers `
    -Form $form
```

  "updatedAt": null

## Responses

- `201 Created` after the file is uploaded and metadata is created.
- For source video uploads, `201 Created` also means a processing job was created and queued.
- `400 Bad Request` for validation errors.
- `404 Not Found` when a supplied catalog relation does not exist.
- `409 Conflict` if the generated storage key is already used.
- `500 Internal Server Error` when object storage upload fails unexpectedly.

## Local MinIO Setup

Start local services:

```bash
docker compose up -d
```

Default local object storage configuration:

```text
ObjectStorage__Endpoint=localhost:9000
ObjectStorage__AccessKey=minioadmin
ObjectStorage__SecretKey=minioadmin
ObjectStorage__BucketName=zinema-media
ObjectStorage__UseSsl=false
ObjectStorage__EnsureBucketExists=true
ObjectStorage__PublicBaseUrl=http://localhost:9000/zinema-media
```

When `EnsureBucketExists` is `true`, the API checks for the bucket and creates it when needed.
